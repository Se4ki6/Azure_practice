# Azure 基礎知識

## 🌐 Azure とは？

**Microsoft Azure**は、マイクロソフトが提供するクラウドコンピューティングサービスです。世界中のデータセンターを通じて、コンピューティング、ストレージ、ネットワーキングなどの IT リソースをインターネット経由で提供します。

## ☁️ クラウドサービスの基本概念

### 従来の方法 vs クラウド

| 従来の方法               | クラウド                         |
| ------------------------ | -------------------------------- |
| 物理サーバーを購入・設置 | 必要な分だけリソースを借りる     |
| 初期費用が高額           | 初期費用が少ない                 |
| 容量の変更が困難         | 必要に応じて簡単にスケール       |
| 保守・管理が必要         | 保守・管理はクラウド事業者が実施 |

### クラウドの利点

- **コスト効率**: 使った分だけ支払う従量課金制
- **スケーラビリティ**: 需要に応じてリソースを増減
- **可用性**: 高い稼働率とバックアップ体制
- **グローバル展開**: 世界中のデータセンターを利用可能

## 🏗️ Azure の基本構造

### 1. サブスクリプション (Subscription)

- **役割**: 課金とアクセス制御の最上位単位
- **例**: 個人アカウント、企業の部署ごとなど
- **重要**: すべてのリソースはサブスクリプション内に作成される

### 2. リソースグループ (Resource Group)

- **役割**: 関連するリソースをまとめる論理的なコンテナ
- **例**: Web サイト用、テスト環境用、本番環境用など
- **特徴**:
  - リソースグループを削除すると、中身のリソースもすべて削除
  - 課金情報をグループ単位で確認可能

### 3. リソース (Resource)

- **役割**: 実際のサービス（仮想マシン、データベース、ストレージなど）
- **例**: ストレージアカウント、仮想ネットワーク、Web App など

### 4. リージョン (Region)

- **役割**: Azure のデータセンターの物理的な場所
- **日本のリージョン**:
  - `Japan East` (東日本) - 東京
  - `Japan West` (西日本) - 大阪
- **選択基準**: レイテンシ、コンプライアンス、コスト

## 🗂️ このプロジェクトで使用する Azure サービス

### Azure Storage Account

- **目的**: ファイル、画像、動画などのデータを保存
- **種類**:
  - **Blob Storage**: オブジェクト（ファイル）ストレージ
  - **File Storage**: ファイル共有
  - **Queue Storage**: メッセージキュー
  - **Table Storage**: NoSQL データベース

### ストレージアカウントの特徴

#### パフォーマンス階層

- **Standard**: 一般的な用途、コスト効率が良い
- **Premium**: 高性能が必要なアプリケーション向け

#### レプリケーション (冗長化) オプション

- **LRS (Locally Redundant Storage)**: 同一データセンター内で 3 回複製
- **ZRS (Zone Redundant Storage)**: 同一リージョンの複数ゾーンで複製
- **GRS (Geo Redundant Storage)**: 地理的に離れたリージョンに複製
- **RA-GRS**: GRS + セカンダリリージョンからの読み取り可能

### Blob Storage の階層

#### アクセス層

- **Hot**: 頻繁にアクセスされるデータ
- **Cool**: 月 1 回程度アクセスされるデータ
- **Archive**: 年数回程度アクセスされるデータ（最安）

#### コンテナのアクセスレベル

- **Private**: 認証が必要（デフォルト）
- **Blob**: Blob 単位で匿名アクセス可能
- **Container**: コンテナ内のすべての Blob に匿名アクセス可能

## 💰 料金体系

### 主な課金要素

1. **ストレージ使用量**: 保存しているデータの容量
2. **トランザクション**: データの読み書き回数
3. **データ転送**: インターネットへの送信データ量
4. **リクエスト数**: API へのアクセス回数

### コスト最適化のポイント

- 不要なリソースは定期的に削除
- 適切なアクセス層を選択
- リージョンはアプリケーションに近い場所を選択
- 開発・テスト環境は夜間・休日に停止

## 🔒 セキュリティの基本

### 認証・認可

- **Azure Active Directory (AAD)**: ID 管理サービス
- **Role-Based Access Control (RBAC)**: 役割ベースのアクセス制御
- **アクセスキー**: ストレージアカウントへの認証情報

### セキュリティのベストプラクティス

- 最小権限の原則を適用
- アクセスキーの定期的な更新
- ネットワークアクセス制御の設定
- 監査ログの有効化
